# Actividad 1 de Desarrollo de Sistemas Informáticos

Empieza por **GUIA_COMANDOS_GIT_BASH.md**. Contiene todos los pasos, desde crear el repositorio hasta publicar `v1.0.0`.

| Carpeta | Contenido |
|---|---|
| 00_inicio | README y reglas de exclusión para iniciar master y develop |
| 01_analisis | Primer Word y PDF con alcance, actores y requerimientos |
| 02_uml | Segundo Word y PDF, casos de uso y clases UML |
| 03_patrones | Tercer Word y PDF, explicación de patrones, arquitectura, secuencia y código |
| 04_final | Word y PDF completos, código, diagramas, Gitflow y espacios para evidencias |

Las versiones son acumulativas. **Cada una usa los mismos nombres internos** `docs/Actividad_1.docx` y `docs/Actividad_1.pdf`. Así Git puede conservar su historial al reemplazarlos. No subas estas cinco carpetas en un solo commit.

El Word utiliza la plantilla institucional suministrada, conserva su portada y encabezado y actualiza el período a septiembre 2026–enero 2027. Completa tu nombre y paralelo en cada avance que publiques. El docente de la plantilla se conserva.

El prototipo implementa Factory Method, Observer y Adapter, más organización MVC. Usa la biblioteca estándar de Python 3.10 o superior. Se ejecuta con `python -m rescate.demo` y se verifica con `python -m unittest discover -s tests -v` desde la raíz del repositorio en los avances 3 o 4.

El informe de `04_final` requiere todavía tus datos, el enlace público y tres capturas de tu ejecución. Reemplaza esos campos antes de entregar. La guía explica cuándo tomarlas. No se han inventado publicaciones ni capturas de GitHub.

La plataforma solicita **PDF**. Usa el Word para completar las evidencias y exporta nuevamente el PDF antes del último commit y de subirlo al aula.
